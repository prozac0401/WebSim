# 공통 프로그램과 동시 실행 규칙

기존 숫자 ID 1~15의 지도는 기존 실행기를 그대로 사용한다. 벽/지도 밖으로 이동하면 실패하고, 집에 도착한 순간 종료한다. 새 `robots` 지도는 상자 도입을 위한 로봇 한 대 지도도 포함해 다음 규칙을 사용한다. **막힌 행동도 한 턴을 쓰고 다음 명령으로 진행한다.**

## 지도와 완료

`rows`는 기존 `#` 벽, `.` 바닥, `*` 표식을 사용한다. 각 로봇은 `{id, x, y, dir, home:{x,y}}`로 배치하고, `boxes`와 `targets`는 `{x,y}` 배열이다. `start`는 기존 화면과의 호환 별칭으로 둘 수 있지만 동시 실행의 출발점은 `robots`다. 집은 각 로봇의 `home`이 기준이며, `H`를 쓰면 실제 집 좌표와 일치해야 한다. 엔진은 잘못된 좌표, 중복 로봇 이름/출발점/집, 로봇과 상자의 겹친 출발점, 상자/목적지 중복, 상자와 목적지 수 불일치, 집과 목적지 중복을 거부한다. 초기 콘텐츠는 로봇 한 대 또는 두 대이며 엔진의 안전 한도는 여덟 대다.

상자는 서로 교환 가능하다. **모든 목적지에 상자가 있고 모든 로봇이 각자 자기 집에 있을 때만** 완료한다. 남의 집은 자신의 집이 아니다. 집에 먼저 간 로봇도 계속 명령을 실행하고, 목적지의 상자도 다시 밀 수 있다. 프로그램을 마친 로봇은 마지막 칸에 남아 장애물 역할도 유지한다. 모두 종료해도 전체 목표가 미완료면 이유와 함께 실행이 종료된다.

## 턴 순서

1. 모든 로봇과 상자의 턴 시작 위치를 고정한다.
2. 로봇마다 공통 프로그램을 자신의 명령 위치에서 해석한다. 조건, 반복 제어, 함수 진입/복귀를 처리하고 다음 물리 행동 하나를 결정한다.
3. 그 시작 상태에서 이동 및 밀기 가능성을 판정하고 모든 행동의 목적 칸 충돌을 함께 판정한다.
4. 취소되지 않은 행동만 한꺼번에 반영한다. 밀기는 로봇과 상자의 위치 변경을 하나로 취급한다.
5. 전체 논리시간을 한 번 증가시킨 뒤 모든 로봇의 위험칸을 검사한다. 종료한 로봇도 포함한다.
6. 위험 실패가 없을 때 전체 목표 달성을 검사한다.

이동·좌/우회전·대기는 한 턴이다. 막힌 이동도 한 턴이다. 조건·반복 제어·함수 진입/복귀는 논리시간을 늘리지 않는다. 아무 로봇도 물리 행동을 하지 않고 프로그램이 끝나면 추가 턴을 만들지 않는다. 실제 애니메이션 길이, 재생 속도, 일시정지 시간은 여기에 관여하지 않는다. 시간 0에 로봇이 위험칸에 있으면 실행 전에 실패한다.

각 로봇은 명령 위치, 반복 프레임, 호출 스택을 따로 보유한다. 공통 프로그램은 실행 시작에 안전한 필드만 복제한다. 편집이나 외부 스냅샷 수정은 이미 실행 중인 프로그램/지도에 영향을 주지 않는다. 전역 저장 한도 128노드, 중첩 4단계, 호출 깊이 2, 재귀 금지는 그대로다. 전체 로봇의 제어/물리 실행 수 합계는 레벨의 `maxSteps`(최대 1,000), 복귀까지 포함하는 별도 평가 안전 한도는 2,000이다. 제어만 반복해도 실행 한도에 도달하면 멈춘다. 도중 한도를 넘은 턴은 어떤 로봇의 물리 행동도 반영하지 않는다.

## 밀기와 충돌

앞에 상자가 하나 있고 그 바로 다음 칸이 빈 바닥이면 상자를 한 칸 밀고 로봇도 전진한다. 미는 방향으로 상자가 이어져 있으면 불가능하다. 옆에 붙은 상자는 영향을 주지 않는다. 벽, 지도 밖, 턴 시작에 다른 로봇이 있던 칸으로는 상자를 밀 수 없다. 당기기, 상자 연쇄 밀기, 여러 로봇의 힘 합치기는 없다.

- 같은 상자를 동시에 밀려는 행동은 전부 취소한다.
- 이동하는 로봇과 밀리는 상자의 목적 칸을 함께 비교한다. 같은 칸을 요구하는 행동은 전부 취소한다. 이동/밀기, 밀기/밀기도 동일하다.
- 다른 로봇의 턴 시작 칸은 그 로봇이 이번 턴에 떠나더라도 들어갈 수 없다. 따라서 자리 맞교환과 뒤따라 바로 진입하기도 불가능하다.
- 이번 턴에 옮겨질 예정인 상자도 시작 상태에서는 상자이므로 연쇄 밀기를 허용하지 않는다.
- 충돌과 관계없는 행동은 정상 수행한다. 로봇 순서나 번호로 어느 한쪽을 통과시키지 않는다.

모든 목적지 충돌은 시작 상태에서 가능한 이동/밀기 의도를 함께 비교해 결정한다. 다른 충돌로 취소된 의도를 없애고 다시 승자를 고르는 재협상은 없다. 실행 한도 진단의 재현성을 위해 내부 제어 해석은 ID 순으로 진행하지만, 한도 실패는 전체 턴을 취소하며 ID로 물리 행동의 승자를 선택하지 않는다.

## 조건과 관찰 API

조건은 자신을 기준으로 **공통 턴 시작 상태만** 읽는다. 경쟁 로봇의 예정 행동은 보지 않는다.

| 조건 | 의미 |
| --- | --- |
| `blocked` | 지금 앞으로 이동/밀기를 시도하면 벽·지도 밖·로봇·연속 상자 때문에 불가능한가? 밀 수 있는 상자는 막힘이 아니다. |
| `mark` | 현재 로봇 칸에 별 표식이 있는가? |
| `box` | 바로 앞에 상자가 있는가? 밀 수 없는 상자도 참이다. |
| `home` | 현재 자신의 집 위에 있는가? |

`runner.step()` 한 번은 동시 모드에서 한 물리 턴이다. 스냅샷은 `mode:'cooperative'`, `robots`, `boxes`, `targets`, 전체 논리시간 `movementCount`, 전체 실행 수 `steps`, 평가 수 `evaluations`를 제공한다. `robots`마다 `currentId`, `callStack`, `repeatStack`, `steps`, `status`, `event`, `message`가 있다. 첫 로봇의 `{x,y,dir}`는 이전 UI를 위한 `robot` 별칭으로 제공한다.

턴 이벤트의 `actions`는 로봇별 실제 명령 ID, 행동 종류(`move`, `push`, `turn`, `wait`), 출발/목적 좌표, 상자 출발/목적 좌표, `cancelled`, 실패 `reason`, 한국어 `message`, 해당 행동까지 거친 제어 흐름 `controls`를 제공한다. 성공한 밀기는 `type:'push', cancelled:false`, 실패한 밀기는 `type:'push', cancelled:true`다. 이유는 `wall`, `robot`, `box-wall`, `box-chain`, `box-robot`, `same-box`, `destination`이다. 프로그램을 마친 로봇의 `event.lastAction`에는 마지막 물리 행동이 남는다. 전체 미완료 종료도 `lastActions`와 마지막 막힘 이유를 보존하므로 빠르게 재생한 뒤 원인을 확인할 수 있다. 종료/실패한 실행기에 추가로 `step()`을 호출해도 결과는 바뀌지 않는다.

## 검증

`node --test routine_bot/coop.test.cjs routine_bot/engine.test.cjs routine_bot/hazards.test.cjs`

`coop.test.cjs`는 손으로 정한 좌표·방향·시간·상태를 기준으로 단일 밀기, 옆/연속 상자, 벽/로봇 막힘, 같은 상자/목적지, 교환/뒤따르기, 이동-밀기/밀기-밀기, 다른 상자의 예정 이동, 로봇 배열 순서, 조건 의미, 분기·반복·호출 독립성, 종료 로봇, 귀가 후 재출발, 배송 후 재밀기, 동시 전체 목표, 위험 우선순위, 제어만 반복하는 안전 한도, 취소/복제/지도 검증을 검사한다. 기존 15레벨과 시간 위험의 원래 좌표·이벤트 회귀 검사는 별도로 유지한다. 이것은 실행 규칙 검증이며 실제 UI 플레이 또는 사람의 재미 검증을 뜻하지 않는다.
