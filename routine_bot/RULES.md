# 루틴봇 실행 규칙

이 문서는 화면, 실행기, 저장기, 시험에서 함께 사용하는 규약이다. 게임은 별도 서버 계산 없이 `engine.js`의 구조화된 명령만 해석한다. 문자열을 JavaScript로 실행하거나 `eval`을 사용하지 않는다.

## 지도와 도착

- 좌표는 왼쪽 위가 `(0, 0)`이다. x는 오른쪽, y는 아래로 증가한다.
- 방향은 `0=북`, `1=동`, `2=남`, `3=서`이다. 앞으로는 현재 방향의 인접한 한 칸으로 이동한다.
- 좌회전과 우회전은 제자리에서 각각 90도 회전한다. 화면 기준이 아니라 로봇 기준이다.
- `#`는 벽, `.`는 길, `*`는 별 표식이 있는 길, `H`는 집이다. 지도 바깥은 벽이다. 시작 위치와 방향은 별도로 기록한다.
- 앞으로 명령이 벽을 가리키면 이동하지 않고 그 명령과 충돌할 칸을 기록한 뒤 실패한다. 벽을 뚫거나 다음 명령을 실행하지 않는다.
- 저장 블록 제한을 통과한 프로그램으로 집에 들어온 순간 성공하고 **남아 있는 모든 명령을 실행하지 않는다.** 반복의 마지막 회전, 함수 복귀, 후속 명령도 생략한다. 실행되지 않는 뒷부분의 블록도 실행 시작 전 저장 수 검사에는 포함한다.
- 여러 지도가 있는 레벨은 한 프로그램을 수정 없이 첫 지도부터 모든 지도에서 성공해야 통과한다. 지도 미리 보기로 고른 지도가 출발 지도를 바꾸지는 않는다.

## 명령 데이터

프로그램의 형태는 `{main: [], F1: [], F2: []}`이다. 모든 명령은 겹치지 않는 1~80자 문자열 `id`를 갖는다.

```js
{ id: 'a', type: 'forward' }                 // 앞으로
{ id: 'b', type: 'left' }                    // 왼쪽 회전
{ id: 'c', type: 'right' }                   // 오른쪽 회전
{ id: 'd', type: 'repeat', count: 3, body: [] }
{ id: 'e', type: 'if', condition: 'blocked', then: [], else: [] }
{ id: 'f', type: 'if', condition: 'mark', then: [], else: [] }
{ id: 'g', type: 'call', target: 'F1' }
```

- `main`에서 위에서 아래 순서로 실행한다. 빈 프로그램이나 집에 못 간 채 끝난 프로그램은 “명령이 끝났어요” 안내로 종료한다.
- 반복은 안쪽 명령 묶음을 정확히 `count`번 실행한다. 매 반복의 시작을 시각적 이벤트로 노출한다. 빈 반복 묶음도 반복 시작 이벤트를 소비한다.
- 조건은 그 블록에 도달한 순간 한 번 평가한다. `blocked`는 현재 방향의 앞 칸이 벽인지, `mark`는 현재 서 있는 칸이 `*`인지 검사한다. 조건 안에서 움직여도 이미 선택한 분기는 바뀌지 않는다. 참이면 `then`, 거짓이면 `else`만 실행한다.
- 비어 있는 분기는 아무것도 하지 않고 다음 명령으로 간다. 조건 뒤의 공통 명령을 사용할 수 있다.
- 함수 부르기는 해당 보관함의 처음부터 실행하고 끝나면 호출 블록 바로 다음으로 돌아온다. 함수 안에서 회전하거나 이동한 상태는 그대로 유지한다.
- **재귀와 순환 호출은 허용하지 않는다.** F1→F1, F2→F2, F1→F2→F1을 모두 거부한다. 실행되지 않는 분기나 쓰지 않는 함수에 있는 순환도 거부한다. F2→F1 또는 F1→F2의 두 겹 호출은 가능하다.
- 함수 정의는 선언이며 그 자체로 실행되지 않는다. 부르기 블록이 필요하다. 빈 함수는 진입·복귀 이벤트만 내고 계속한다.

## 두 종류의 수

**저장 블록 수**는 세 보관함에 저장한 모든 블록을 한 번씩 센다. 반복 상자, 조건 상자, 양쪽 분기의 안쪽 블록, 사용하지 않는 함수도 포함한다. 같은 함수를 여러 번 부르면 각 호출 블록은 각각 세지만 함수 본문은 한 번 센다.

**실행 횟수**는 실제로 처리한 이동, 회전, 조건 판정, 함수 호출, 반복 시작의 수다. 반복은 매 회 시작마다 1회가 더해진다. 함수 복귀는 위치를 알려 주는 시각적 이벤트로 표시하지만 실행 횟수를 늘리지 않는다. 충돌을 시도한 이동은 실행 횟수에 포함한다. 다중 지도 결과는 각 지도 실행 횟수를 더한다.

**레벨별 저장 블록 상한은 제작자가 정한 기준 프로그램의 전체 저장 노드 수와 같다.** 1~15번 상한은 각각 `3, 5, 6, 2, 5, 7, 4, 4, 6, 11, 9, 6, 9, 10, 9`개다. 이는 실행에 필요한 제한이며 별도의 선택 배지 목표가 아니다. 이동·회전·반복 등 종류마다 할당을 두지 않고 전체 저장 수만 제한한다. 상한 이하의 다른 프로그램도 집에 도착하면 통과한다. 기준 프로그램과 동일한 구조를 요구하지 않으며, 이 수를 최소 블록 수나 최적해로 주장하지 않는다.

실제 게임은 `levels.js`에 기록된 상한으로 검사한다. 제작자 해답인 `solutions.cjs`는 검증 도구에서만 사용하고 게임에서 불러오지 않는다.

## 제한과 실패 처리

| 항목 | 상한 / 규칙 |
| --- | --- |
| 저장 블록 | 전역 128개, 각 레벨은 기준 프로그램의 전체 저장 노드 수로 제한 (`levels.js`) |
| 상자 중첩 | 반복·조건 상자를 4겹까지, 각 함수 보관함에서 별도로 계산 |
| 반복 횟수 | 정수 2~12회 |
| 함수 호출 | 최대 두 겹, 순환·재귀 금지 |
| 실행 횟수 | 전역 1,000회, 레벨별 더 작은 상한은 `levels.js` |
| 지도 | 직사각형, 최대 30×30, 집 정확히 1개, 시작은 길·별·집 위 |
| 추가 필드 | 실행할 때 필요한 허용 필드만 복사하며 임의 메타데이터는 무시 |

저장 블록 상한을 넘는 프로그램은 한 단계도 실행하지 않고 거부한다. 실행 횟수 상한까지의 명령은 실행할 수 있으며, 다음 명령이 실행 횟수 상한을 넘으면 적용하기 전에 멈춘다. 실행 상한의 마지막 이동으로 집에 도착하면 성공이다. 실패는 상태와 한국어 이유를 반환하며 예외로 전체 화면을 중단하지 않는다. 편집과 실행 시작에 같은 `validate()`의 구조·상한 검사를 사용한다.

이전 버전에서 저장한 프로그램이 새 저장 상한을 넘었다는 이유만으로 삭제하지 않는다. 코드를 보존한 채 초과 상태를 안내하고, 블록을 줄여 상한에 맞추면 다시 실행할 수 있다. 줄이는 도중 아직 상한을 넘더라도 부분 삭제를 허용한다. 상한 이하의 새 프로그램에서 예산을 넘기는 추가는 거부한다.

## 실행 API와 취소

`RoutineEngine` 브라우저 전역과 CommonJS `require('./engine.js')`는 같은 API를 제공한다.

```js
const check = RoutineEngine.validate(program, level); // {ok, errors, count}
const runner = RoutineEngine.createRunner(program, level, mapIndex = 0);
runner.snapshot(); // 현재 상태의 독립 복사본
runner.step();     // 최대 하나의 화면 이벤트를 처리한 상태
runner.cancel();   // 아직 진행 중인 실행을 영구 취소
```

상태는 `{status, robot, steps, event, currentId, message, callStack, collision, mapIndex}`이다. `status`는 `ready`, `running`, `success`, `failure`, `cancelled` 중 하나다. 이벤트는 `move`, `turn`, `condition`, `repeat`, `call`, `return`, `success`, `failure`, `cancel`이다. 성공 이벤트에는 원래 행동 종류 `action`을 포함한다. 조건에는 `result`, 반복에는 `iteration`과 `count`, 호출과 복귀에는 `target`이 있다.

실행기는 동기적으로 한 이벤트만 반환하고 내부 타이머를 만들지 않는다. 생성 시 프로그램의 허용 필드를 복사하므로 편집 중 원본을 바꿔도 진행 중인 실행이 변하지 않는다. 종료·취소 뒤 `step()`을 다시 불러도 상태는 바뀌지 않는다.

화면은 단일 업데이트 시계와 실행 세대 번호로 진행한다. 일시정지는 시계를 멈추고 이어서 실행할 상태를 유지한다. 초기 위치, 편집, 지도 미리 보기, 레벨 전환은 이전 실행을 취소하고 애니메이션과 성공 전환을 비운다. 초기 위치로 돌아가는 동작은 저장 프로그램을 지우지 않는다. 프로그램 삭제는 별도 편집 동작이며 실행 취소로 되돌릴 수 있다.

## 재현 검사

```sh
node --test routine_bot/engine.test.cjs
```

엔진 시험은 미리 손으로 적은 좌표·방향·이벤트 순서와 비교한다. 전체 레벨 검사는 별도 `solutions.cjs`의 기준 프로그램을 **게임과 같은 실행기**로 돌린다. 기준 프로그램은 실제 게임 HTML에서 불러오지 않는다. 제한·의도·기준해답은 [LEVELS.md](LEVELS.md)에 기록했다. 저장·브라우저·정적 경로까지 포함하는 절차는 [README.md](README.md)와 프로젝트 `game-verification`, `game-playtest` 스킬을 따른다.
