# 레벨 설계와 기준 프로그램

기존 숫자 ID 1~15와 18지도는 지도·도구·상한·기준 프로그램을 그대로 유지한다. 사이에 안정적인 문자열 ID를 가진 9단계·10지도를 넣어 현재 **24단계·28지도**다. `levels.js`의 순서와 `displayOrder`는 표시 순서이고, `id`는 저장 프로그램의 영구 식별자다. `prerequisites`가 해금 관계를 기록한다. 기존 완료·진행 저장의 접근 권한은 새 단계 삽입으로 회수하지 않는다.

**각 레벨의 저장 블록 상한은 그 레벨 기준 프로그램의 저장 노드 수와 같다.** 기준 프로그램은 가능성을 입증하는 제작자용 해답이며 최적해로 주장하지 않는다. 실제 게임은 이 문서나 `solutions.cjs`를 읽지 않고 `levels.js`에 기록한 상한만 사용한다. 사용된 기능과 반드시 필요한 기능은 아래 사전 검토 및 증명 표에서 구분한다.

표기: `앞`=앞으로, `왼`/`오`=제자리 회전, `쉼`=한 박자 기다리기, `반복 n[…]`=정해진 횟수 반복, `벽? 예[…] 아니요[…]`=앞이 막혔는지 검사, `별?`=현재 타일의 별 검사. `F1()`/`F2()`는 함수 호출이다. 비어 있는 분기는 `[]`이다. `길읽기`는 문서에서만 쓰는 약칭으로, 게임의 새로운 명령은 아니다.

`길읽기 = 벽? 예[오] 아니요[별? 예[왼] 아니요[], 앞]`

지도는 `levels.js`에서 행 문자열과 시작 좌표로 정의한다. 별은 색과 별 모양을 함께 사용한다. 8·9·13·15번의 별 너머에는 짧은 막다른 길이 있어 별이 없는 벽 추종과 다른 판단이 필요하다. 12·15번의 각 지도는 처음 상태부터 별도로 실행하며 이전 지도 위치나 실행 상태를 이어받지 않는다.

기존 시간 위험은 5·8·12·15번의 7지도에 배치했다. 추가 위험은 `wait-beat`와 마지막 `coop-finale`에만 있다. 처음 상자·협동을 배우는 지도에는 위험을 섞지 않는다. 논리시간은 앞으로·좌회전·우회전·기다리기마다 1 증가하며, 협동에서는 로봇 수와 무관하게 전체 턴당 한 번 증가한다. 반복·조건·호출·복귀는 논리시간을 증가시키지 않는다. 위험은 `t % period`가 `activePhases`에 포함될 때 켜진다. 행동 뒤 켜진 칸에 있으면 제자리 회전·기다리기도 실패하며, 전체 목표 달성보다 위험 판정이 우선이다. 일시정지·벽시계 대기·재생 속도는 시간표를 바꾸지 않고, 새 지도는 시간0에서 시작한다.

| 레벨/지도 | 위험칸 `(x,y): 주기 / 켜지는 나머지` | 타이밍 의도와 독립 예상 |

저장 상한은 선택 배지 목표가 아니라 실행에 필요한 제한이다. 시작·F1·F2의 모든 저장 노드를 합하며, 반복·조건 상자 자체와 양쪽 분기도 센다. 이동·회전 등 종류별 사용 개수를 따로 제한하지 않는다. 상한 이하에서 해결하는 다른 프로그램도 허용하므로 기준 프로그램과 구조가 같거나 블록 수가 정확히 같을 필요는 없다. 예를 들어 4번은 상한 2개 안에서 반복과 이동을 조합해야 하며, 앞으로 다섯 개를 나열하는 프로그램은 실행할 수 없다. 실제 실행 횟수는 별도의 한도를 사용한다.

도착 즉시 끝나는 규칙 때문에 기준 프로그램의 마지막 회전이나 남은 반복은 실행되지 않을 수 있다. 예를 들어 5번은 마지막 계단의 앞으로에서 도착하고 마지막 왼쪽 회전을 생략한다. 11번은 F1 안에서 도착하므로 남은 함수 복귀가 없다.

## 검증과 증거

```sh
node --test routine_bot/engine.test.cjs
node --test routine_bot/hazards.test.cjs
node --test routine_bot/necessity.test.cjs
node --test --test-name-pattern="reference level [123]:|coordinates|turns|wall collision|early collision" routine_bot/engine.test.cjs
```

첫 명령은 손으로 예상한 독립 엔진 시험과 15개 레벨의 모든 지도를 검사한다. 저장 상한은 별도로 손으로 센 고정 수열 `3, 5, 6, 2, 6, 7, 4, 5, 6, 11, 9, 7, 9, 10, 11`과 비교하고, 각 기준 프로그램의 저장 수가 상한과 정확히 같은지 검사한다. 기준 프로그램 뒤에 블록 한 개를 더한 프로그램은 집 뒤의 실행되지 않는 명령이라도 시작 전에 거부되는지 확인한다. 같은 기준 프로그램으로 18개 지도 모두의 해결 가능성을 계속 검사한다. 위험 레벨 전용 시험은 위 표의 실패 칸·시각과 성공 시각을 손으로 정한 값과 비교한다. 마지막 명령은 초반 3레벨의 작은 재현 집합이다. 해답 실행은 프로그램 편집 UI의 사용성 검사가 아니다. 실제 블록 추가·수정·실행으로 하는 조작과 기록을 구분한다. 실행 로그와 화면 증거의 위치는 [README.md](README.md)의 검증 절차를 따른다.

## 삽입 순서와 새 학습 단계

`function-reuse`의 도구 제한은 함수 재사용을 독립적으로 학습하는 **그 단계만의 공개 언어 규칙**이다. 본문과 첫 힌트에 반복·조건·기다리기를 제공하지 않는다고 안내한다. 일반 레벨의 도구를 사후 제한하거나 ‘호출 1회’ 같은 형식적인 통과 조건을 추가하지 않는다. 기다림 도전도 같은 방식으로 두 도구를 공개한다. 초기 상자·협동 도입은 연결된 튜토리얼 설명 후 그 지도를 직접 편집하고 해결하므로 별도 중복 연습 맵은 없다.

### 필수성 증명과 반례 관리

`necessity.test.cjs`는 기준 풀이를 실제 `createRunner`로 실행하면서 독립적인 아래 불가능성 검사도 수행한다. 중단·시간 초과는 실패 또는 미검증이며 해답 없음으로 처리하지 않는다. ‘기준 풀이에서 블록 하나를 지웠더니 실패’는 이 증명과 구별한다.

1. **반복(기존 4)**: 5번 전진해야 하지만 반복 없는 도구는 이동·회전뿐이고 노드 상한은 2다. 길이 0~2의 13프로그램을 모두 검사한다.
2. **기다림**: 홀수 턴에 켜지는 바로 앞 집이다. 제공 도구는 앞으로와 기다리기이고 상한은 2. 기다리기를 뺀 빈 코드/앞/앞앞 3개 모두 실패하며 쉼·앞은 2턴에 성공한다. 회전은 이 작은 학습 언어에 없으므로 회전으로 시간을 맞추는 반례는 유효 프로그램이 아니다.
3. **조건**: 지도 1에서 첫 이동이 가능한 방향은 동쪽뿐, 지도 2에서는 북쪽뿐이다. 조건 없는 결정적 프로그램은 같은 첫 이동 방향을 요구하므로 적어도 한 지도에서 실패한다. 별·벽을 읽지 않는 모든 문법(앞/왼/오/쉼, 빈 반복 포함, 2~12회 반복, 중첩 포함)을 상한 3까지 전수 생성한다. 노드 비용별 수는 1, 15, 390, 12,615로 합계 **13,021개**다. 조건 없는 함수도 이 단계에서는 잠겨 있다.
4. **함수**: 회전까지 포함한 위치·방향 BFS의 최단 경로는 8행동이다. 함수 없는 7노드 프로그램은 최대 7행동만 실행하므로 도달할 수 없다. 길이 0~7의 앞/왼/오 **3,280개**를 실제 엔진으로 전수 검사한다. 호출되지 않는 F1 정의는 실행에 영향을 주지 않고 상한만 사용한다. 7노드 함수 풀이가 8턴에 성공하므로 불필요한 호출 조건 없이 실질적인 압축을 요구한다.
5. **상호 도움**: `coop-gate`/`coop-finale`의 상자는 `(3,2)`, 목적지는 `(3,3)`, A는 왼쪽 `(1,2)`, B는 상자 위 `(3,1)`에서 시작한다. A가 처음 상자를 오른쪽으로 밀면 상자는 위/아래가 벽인 수평 통로에 갇히고 A는 오른쪽 미는 면에 접근할 수 없다. A에게 회전을 공짜로 주고, 코드/턴 제한·위험·B를 모두 제거한 더 유리한 규칙에서도 가능한 상태는 상자 x=3에서 2, x=4에서 5, x=5에서 6, 합계 **13상태**뿐이며 목적지에 도달하지 못한다. B가 아래로 밀면 A가 통과할 수 있다. 실제 공통 코드가 8/10턴에 성공함도 별도로 확인한다.
6. **상자 분리**: 첫 `앞`은 두 연속 상자를 만나 제자리에서 1턴을 소비하고 상자는 그대로다. 아래 `(3,3)` 목적지는 수직 밀기가 필요하고, 기준 코드는 위쪽에서 접근해 오른쪽 상자를 먼저 내린 뒤 돌아와 나머지를 오른쪽으로 민다. 옆으로 붙은 상태에서 수직 밀기는 정상 허용한다.

통합 응용의 위험칸 `(4,2)`는 주기4의 위상2·3에 켜진다. 일반 길열기 코드로 빠르게 통과하면 7턴에 실패하고, F1의 쉼·앞 코드는 8·9턴에 그 칸에 머물고 10턴에 나가 성공한다. 4턴에는 B가 떠날 예정이어도 턴 시작에 B가 있던 칸으로 들어가지 못해 A의 전진 하나가 취소된다. 이 취소도 명령과 턴을 소비하며 다음 반복에서 재시도한다.

### 버전과 보존

각 레벨은 `version: 1`과 규칙 버전을 가진다. 기존 실행기는 `solo-1`, 새 상자/협동 실행기는 `simultaneous-1`이다. 앞으로 지도·도구·상한을 바꾸면 `version`, 실행 규칙을 바꾸면 `rulesVersion`을 올려 다른 조건의 시간 기록을 섞지 않는다. 기존 ID 1~15를 표시 위치에 따라 다시 번호 붙이지 않는다. 이전의 무시간 완료 기록에 가짜 0초를 만들지 않으며 저장 이전/진행 접근 시험은 저장 시험과 UI 시험으로 따로 확인한다.

## 기록한 가역적 결정

- 요구에 있는 “12레벨·4챕터”를 본편으로, 13~15번을 본편 이후 응용 3레벨로 해석했다.
- 본편 1~3에서는 반복·조건·함수 블록을 숨긴다. 4부터 반복, 5부터 기다리기, 7부터 벽 조건, 8부터 별 조건, 10부터 F1, 11부터 F2를 연다.
- 임의 프로그램 문자열, 온라인 계정, 순환 호출, 자유 지도 제작은 포함하지 않았다.
- 벽 조건은 앞 타일, 별 조건은 현재 타일을 읽는다. 별 판정 후 이동을 공통 명령으로 둘 수 있어 조건 안쪽 편집 부담을 줄였다.
- 2026-10-19 사용자 요청에 따라 각 기준 프로그램의 전체 저장 노드 수를 필수 상한으로 정했다. 종류별 할당은 두지 않으며, 최소·최적 블록 수를 증명한 값으로 표현하지 않는다. 기존 선택 도전 기준은 제거했다.
- 함수 복귀는 읽을 수 있는 화면 이벤트를 유지하면서 실행 횟수에서는 제외했다. 저장 수와 실행 수의 정의는 [RULES.md](RULES.md)에 고정했다.
- 시간 위험 도입 뒤 5·8·12·15의 기준 프로그램에 필요한 기다리기 노드 수만큼 저장 상한을 갱신했다. 반복·조건·함수를 썼다는 이유로 위험 시각이 바뀌지 않도록 논리시간과 실행 수를 구분했다.
