# 루틴봇: 집으로 가는 코드

명령 블록으로 로봇의 귀갓길과 상자 배송을 만드는 2D 퍼즐입니다. 기존 숫자 ID 1~15의 지도·저장 코드를 유지하고 사이에 9개 도전을 통합한 24단계·28지도입니다. 기존 트리 편집기·반복·조건·함수·대기·위험 타일을 사용하며 협동에서는 두 로봇이 하나의 코드를 실행합니다. 외부 서버·프레임워크·CDN·계정이 필요하지 않습니다.

## 협동 확장 안내

- [게임 방법](routine_bot_doc.html): 게임의 도움말은 실행 상태를 보존하며 멈춥니다. 직접 한 턴씩 움직이는 짧은 튜토리얼에서 실제 도입 단계로 연결되고, 완료한 단계를 중복 수행할 필요가 없습니다. 모든 편집과 예시 진행은 탭으로 가능합니다.
- [공통 코드·동시 턴 규칙](COOP-RULES.md): 시작 상태 고정 → 로봇별 다음 물리행동 결정 → 대칭 충돌 판정 → 원자적 이동/밀기 → 위험 → 전체 목표. 로봇별 선택 버튼은 각자의 현재 명령과 호출 상태를 강조합니다. 새 상자 지도는 한 대여도 이 규칙을 사용하며, 막힌 행동은 한 턴을 쓰고 다음 명령으로 진행합니다.
- [레벨 감사와 필수성](LEVELS.md): 기존 기능을 필수로 오분류하지 않고, 작은 도전의 공개 도구·한도에 대한 완전 탐색 또는 지형 증명을 제공합니다. 기존 12레벨의 함수 없는 풀이도 유지합니다.
- [시간·저장 정책](TIMING_STORAGE.md): 도전 시작부터 활성 시간을 측정합니다. 실패·위치 초기화·재실행에 누적하고 도움말·쉬기·숨김을 제외합니다. 새 기록 시작은 별도 동작이며, 최초/최고·도움 여부·지도/규칙 버전을 구분합니다. 저장 키는 유지하고 v1을 v2로 이전합니다.

여정의 표시 순서와 `prerequisites`는 `levels.js` 목록으로 관리합니다. 숫자 ID 1~15는 변하지 않으며 새 ID는 의미 있는 문자열입니다. 완료했거나 이미 해금한 기존 지도는 중간 삽입으로 다시 잠기지 않습니다. `records`에 시간이 없는 완료를 0초로 바꾸지 않습니다.

## 실행과 진입

저장소 루트에서 다음 명령을 실행합니다.

```sh
node tests/routine-bot-server.cjs
```

`http://127.0.0.1:8123/WebSim/`의 게임 목록에서 **루틴봇: 집으로 가는 코드**를 선택합니다. 직접 주소는 `http://127.0.0.1:8123/WebSim/routine_bot/routine_bot.html`입니다. `PORT` 환경 변수로 포트를 바꿀 수 있습니다. 배포 파일은 저장소에 있는 정적 HTML/CSS/JavaScript 그대로이며 빌드 단계가 없습니다. `/WebSim/` 접두 경로를 포함하는 서버는 GitHub Pages 프로젝트 경로의 상대 링크도 함께 검사합니다.

블록을 눌러 넣고 **실행**합니다. 블록을 선택하면 같은 가지에서 그 뒤에 삽입하고, **이 범위 맨 뒤에 넣기**를 누르면 해당 가지의 마지막 위치로 돌아갑니다. 선택한 블록을 앞으로/뒤로 옮기거나 삭제할 수 있습니다. 반복·조건의 본문은 부모 아래 들여쓴 가지로 펼쳐지며, 앞뒤 명령도 함께 보입니다. **펼치기 / 접기**는 코드의 표시만 바꿉니다. 가지의 **＋ 추가** 버튼으로 새 블록을 넣을 곳을 고르고 반복 카드에서 횟수를 바꿉니다. 현재 편집 중인 가지를 접으면 삽입 위치가 부모 쪽으로 돌아가 숨은 코드에 명령이 들어가지 않습니다. F1/F2 탭은 함수 본문 편집입니다. 현재 범위 이름과 실행 경로는 별도로 표시합니다.

**멈춤**, **한 단계**, **처음 위치**, **속도**로 실행을 관찰합니다. 처음 위치는 코드를 유지합니다. **코드 비우기**가 프로그램을 지우며 **실행 취소**로 최근 편집을 되돌립니다. 힌트는 관찰할 지점부터 단계적으로 제시합니다. 각 레벨의 **저장 블록 제한 안에서** 집에 도착해야 성공합니다. 제한은 제작자가 마련한 기준해답의 블록 수이며, 증명된 최단·최적해라는 뜻은 아닙니다. 자세한 조작은 [놀이 방법](routine_bot_doc.html)에 있습니다.

## 기존 단일 로봇 실행 규칙 (숫자는 안정 ID)

- 좌표는 왼쪽 위 `(0,0)`에서 오른쪽으로 x, 아래로 y가 증가합니다. 방향은 `0=위, 1=오른쪽, 2=아래, 3=왼쪽`입니다. 지도 문자열은 `#=벽, .=길, *=별 표식, H=집`입니다. 시작 좌표·방향은 지도 데이터에 따로 저장합니다.
- 앞으로는 바라보는 쪽으로 한 칸 이동합니다. 좌/우 회전은 같은 칸에서 90도 회전합니다. 지도 밖은 벽입니다. 충돌하면 이동하지 않고 시도한 칸과 명령을 남기며 실행을 종료합니다.
- 5레벨부터 **한 박자 기다리기**를 쓸 수 있습니다. 앞으로·좌회전·우회전·기다리기마다 논리시간이 1 증가합니다. 반복·조건·함수 호출·복귀는 논리시간을 늘리지 않습니다. 논리시간은 실제 실행 수와 별도이며, 재생 속도·일시정지·현실의 대기 시간에 따라 바뀌지 않습니다.
- 5·8·12·15레벨의 일부 칸은 정해진 주기에 따라 켜집니다. 현재 위험은 **×**, 다음 행동 뒤 위험은 **!**로 표시하며 펼칠 수 있는 시간표를 제공합니다. 행동 뒤 켜진 칸에 있으면 제자리 회전·기다리기도 실패하고 집 도착보다 위험 판정이 먼저입니다. 벽 충돌은 시간1을 소비한 뒤 충돌로 종료합니다. 처음 위치·레벨 전환·다음 지도에서는 논리시간을 0으로 초기화합니다. 위험칸은 벽이 아니므로 앞이 벽인지 검사하는 조건과 별개입니다.
- 조건은 해당 조건 블록에 도달한 시점의 상태로 딱 한 번 평가합니다. `blocked`는 바로 앞이 벽/지도 밖인지, `mark`는 현재 칸이 별 표식인지 검사합니다. 참이면 `then`, 거짓이면 `else`를 실행한 뒤 다음 명령으로 합류합니다.
- 반복은 본문을 지정한 2~12회 실행합니다. 반복 제어 명령은 매 회차 실행 수 1회로 셉니다. 단순 이동/회전, 조건 평가, 함수 호출도 각각 1회입니다. 함수 복귀는 별도의 시각적 실행 이벤트이며 실행 수를 늘리지 않습니다.
- F1/F2는 본문을 실행하고 호출 다음 위치로 복귀합니다. 함수끼리 호출할 수 있지만 재귀·서로 다시 부르는 순환 호출은 허용하지 않습니다. 호출 연결 전체를 편집과 실행 시작 때 검증하며 사용하지 않는 함수 안의 순환도 거부합니다. 함수 호출 깊이는 최대 2입니다.
- 로봇이 집에 도달한 명령 직후 성공으로 종료합니다. 뒤에 남은 명령·반복·함수 복귀는 수행하지 않습니다. 집에 도착하지 못한 채 명령이 끝나면 실패합니다. 여러 지도를 가진 레벨은 동일 프로그램으로 모든 지도를 해결해야 완료됩니다.
- 저장 블록 수는 시작/F1/F2와 모든 분기의 노드 개수를 합합니다. 실행 수는 실제 선택된 분기와 반복만 셉니다. 1~15레벨의 저장 블록 제한은 각각 `3, 5, 6, 2, 6, 7, 4, 5, 6, 11, 9, 7, 9, 10, 11`개입니다. 제한을 넘는 추가·실행은 거부하며 더 적은 블록으로 해결하는 것은 허용합니다. 전역 데이터 한도는 128블록, 내부 중첩은 4단계, 실행은 지도마다 최대 1,000회이며 레벨별 더 작은 한도가 우선합니다. 한도 초과·잘못된 데이터는 이유를 보여 주고 종료합니다.
- 구조화된 명령을 해석하며 `eval`, `Function` 생성자, 사용자 문자열 JavaScript 실행을 사용하지 않습니다. 실행기는 프로그램을 복제하므로 실행 중 원본 편집이 이미 시작한 해석에 끼어들지 않습니다. UI는 실행 취소 및 이전 예약 작업을 무효화해 초기화·레벨 전환 뒤의 오래된 콜백을 차단합니다.

프로그램의 데이터 형태는 다음과 같습니다. 모든 노드의 `id`는 비어 있지 않은 고유 문자열(최대 80자)입니다.

```js
{
  main: [
    { id: 'a', type: 'repeat', count: 3, body: [
      { id: 'b', type: 'if', condition: 'blocked',
        then: [{ id: 'c', type: 'right' }],
        else: [{ id: 'd', type: 'call', target: 'F1' }] }
    ] }
  ],
  F1: [{ id: 'e', type: 'forward' }],
  F2: []
}
```

## 저장과 접근성

진행·레벨별 코드·속도·음소거·시간 기록은 같은 브라우저의 `localStorage`에 저장합니다. 키는 `routinebot-save-v1`, 이전 정상 저장의 보조 키는 `routinebot-save-v1-backup`입니다. 내부 버전 1은 2로 이전합니다. 안정 ID·설정·명령 구조·기록 크기·깊이를 검증하고 알려진 필드만 복제합니다. 깨진 JSON과 지원하지 않는 버전은 보조 저장을 시도합니다. 사용할 저장이 없거나 접근/쓰기 실패가 나면 세션 메모리로 계속 플레이하고 저장 상태를 안내합니다. 보조 저장은 한 단계 이전 상태이며 모든 과거 편집을 복구하는 기록은 아닙니다. 저장을 막은 브라우저에서는 창을 닫은 뒤 복원이 보장되지 않습니다.

이전 버전에서 작성한 코드가 새 레벨별 블록 제한을 넘더라도 자동 삭제하지 않습니다. 현재 코드와 초과 안내를 표시하고 실행·추가를 막으며, 블록을 하나씩 삭제해 제한에 맞출 수 있습니다. 아직 제한을 넘는 중간 수정과 실행 취소도 저장·복원됩니다. 기존 완료 기록은 유지하지만 새 실행에는 현재 제한을 적용합니다.

모든 편집은 클릭/탭만으로 가능합니다. 키보드 Tab으로 버튼을 선택하고 Enter/Space로 누릅니다. Ctrl/Cmd+Enter는 실행/멈춤, R은 처음 위치, Ctrl/Cmd+Z는 실행 취소이며 입력란에서의 키 입력은 가로채지 않습니다. 버튼·링크 밖에서는 Space로도 실행/멈춤을 할 수 있습니다. 색에 더해 별·집·화살표·위험 기호·문구를 사용합니다. 지도 글로 읽기와 위험 시간표를 제공하며 `prefers-reduced-motion`을 존중합니다. 효과음은 초기 음소거이고 사용자 조작 이후 재생합니다. 스크린 리더 전체 사용자 시험은 별도 수행 여부를 검증 보고서에서 확인하세요.

## 검증 명령과 재사용 스킬

```sh
node --test routine_bot/*.test.cjs tests/routine-bot-server.test.cjs
node tests/routine-bot-cooperation.browser.cjs early
node tests/routine-bot-cooperation.browser.cjs final
node tests/routine-bot-deployment.cjs final
node tests/routine-bot.browser.cjs early
node tests/routine-bot.browser.cjs final
node tests/routine-bot-safety.browser.cjs
node tests/routine-bot-tree.browser.cjs
node tests/routine-bot-budgets.browser.cjs
node tests/routine-bot-hazards.browser.cjs
```

HTTP 검사는 먼저 위 정적 서버를 켭니다. 브라우저 검사는 기존 프로젝트와 같은 Playwright를 사용하며 로컬 설치 또는 개발 환경의 `develop-web-game` 런타임을 찾습니다. `WEBSIM_URL`로 다른 서버(반드시 실제 접두 경로 포함)를 지정하고 `WEBSIM_EVIDENCE`로 증거 폴더를 지정할 수 있습니다. 안전성/트리 브라우저 검사는 후반 접근용 진행 fixture를 사용하고 실제 UI로 프로그램을 편집하므로 전체 순차 진행·정답 미열람 탐색과 구분합니다. 안전성 증거는 `final/safety/`, 트리 펼침·접힘·중첩 편집·모바일·키보드 회귀는 `tree/`에 기록합니다. Node 기본 시험은 추가 패키지 없이 실행됩니다. 브라우저 시험 의존성은 게임 배포물에 포함되지 않습니다.

블록 제한 검사는 `budgets/migration/`에 증거를 남깁니다. 이전 한도에서 유효했던 1레벨 5블록 저장만 migration fixture로 넣고, 실제 버튼·터치로 삭제·취소·새로고침·실행을 수행합니다. 성공 상태를 주입하지 않습니다. 별도의 4레벨 접근 fixture는 반복 두 블록으로 해결하는 장면을 검증합니다. fixture 검사를 새 저장부터의 전체 진행이나 블라인드 탐색으로 세지 않습니다.

시간 위험 전용 검사는 `hazards/focused/`에 증거를 남깁니다. 레벨 접근 기록만 fixture로 설정하고, 실제 블록 입력으로 위험 실패·기다리기 삽입·제자리 위험·시간표·멈춤/속도·초기화·함수·별·다음 지도 시간0을 확인합니다. 논리시간은 `movementCount`, 그림의 시각은 `renderedTime`, 위험 상태는 `hazards`/`renderedHazards`로 관찰할 수 있으며 이 값을 주입해 성공시키지 않습니다. `hazards.test.cjs`는 위험 레벨의 예상 실패 칸과 시간을 손으로 정한 값과 비교합니다.

프로젝트 스킬은 [game-verification](../.agents/skills/game-verification/SKILL.md)과 [game-playtest](../.agents/skills/game-playtest/SKILL.md)입니다. Codex에서 프로젝트를 연 뒤 `$game-verification`, `$game-playtest`로 요청할 수 있습니다. [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)의 `.agents/skills/<name>/SKILL.md`와 `name`/`description` frontmatter 형식을 사용했습니다. 이 작업의 기존 세션에서는 신규 스킬의 자동 발견을 확인할 수 없어 파일을 직접 읽고 절차를 실행했습니다. 전역 설정이나 사용자 계정 설정은 바꾸지 않았습니다.

스킬 형식은 기존 `skill-creator/scripts/quick_validate.py`로 검사합니다. 이번 환경에 PyYAML이 없어 `output/tools/skill-validation/`에만 설치해 검사했으며 사용자 전역 Python 설정을 바꾸지 않았습니다. 재실행 시 PyYAML이 있는 Python 또는 격리된 검사 환경을 사용하세요.

레벨별 의도·기준 프로그램·한도는 [LEVELS.md](LEVELS.md), 실행 결과와 정확한 환경은 [VERIFICATION.md](VERIFICATION.md), 실제 조작의 관찰과 수정은 [PLAYTEST.md](PLAYTEST.md)에 있습니다. 기준해답 실행과 정답을 보지 않은 탐색 플레이는 별도 기록입니다. PNG·JSON·실행 로그는 `output/playwright/routine-bot/<early|final|blind>/`에 남기며 이 폴더는 저장소의 기존 정책에 따라 Git에서 제외됩니다.
