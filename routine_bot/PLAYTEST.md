## 추가 독립 키보드 검토와 수정

첫 화면에서 Tab으로 앞으로 버튼을 선택하고 Enter를 두 번 누르면, 기존 구현은 첫 블록 추가 뒤 포커스를 BODY로 잃어 두 번째 입력이 무시됐다(`final/safety/keyboard-before.json/png`). 편집기 재렌더링에서 같은 팔레트/블록에 포커스를 복원하도록 수정했다. 실제 Tab·Enter로 블록3개를 넣고 선택 포커스를 유지한 뒤 Ctrl+Enter로 실행해 첫 레벨을 해결했다. `node tests/routine-bot-safety.browser.cjs --keyboard-only`의 별도1개 회귀 PASS, `final/safety/keyboard/`의 trace·JSON·캡처에 기록했다. 버튼의 Space는 표준 활성화로 유지하고 실행 단축키는 화면에 Ctrl+Enter로 안내한다. 수정 후 데스크톱·320/390터치·저장장애15개 장면도 다시 PASS(`final/keyboard-retest/browser-report.json`).

## 2026-10-19 · 반복·조건을 펼쳐 보는 트리 편집

반복·조건을 편집할 때 해당 범위만 보이던 화면을 같은 함수의 명령 전체가 이어지는 트리로 바꿨다. 부모 아래 들여쓴 본문과 예/아니요 가지를 펼치고 접으며, 앞뒤 명령이 같은 트리에 유지된다. 가지의 추가 버튼은 삽입 위치를 고르고, 펼치기/접기는 표시만 바꾼다. 반복 횟수는 해당 카드에 있다. 현재 편집하는 가지의 조상을 접으면 삽입 위치를 부모로 옮겨 숨은 곳에 추가하지 않도록 했다.

두 프로젝트 스킬을 직접 다시 읽어 적용하고 `tests/routine-bot-tree.browser.cjs`를 추가했다. 이 검사는 본편 1–11 완료 여부만 접근 fixture로 설정하며 코드·실행·성공을 주입하지 않는다. 데스크톱 1440×900, 터치 320×740과 390×844에서 실제 팔레트/가지/선택 버튼으로 중첩 트리를 만들고 고친다. 키보드 장면은 Tab·Enter·화살표로 반복을 편집하고 Ctrl+Enter로 4레벨을 해결한다. 기존 정답 미열람 탐색과 구분한 자동 조작 회귀이며 새 사람의 이해도·만족도 시험은 수행하지 않았다.
