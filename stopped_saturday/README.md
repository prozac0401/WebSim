# 멈춘 토요일 · Saturday, Interrupted

갑작스러운 부상으로 오른쪽 다리에 깁스를 하고 목발을 사용하게 된 인물이, 병원에서 돌아온 뒤 처음 맞는 주말을 다루는 선택형 이야기입니다. 사용자가 제공한 `멈춘토요일_v0.1_소스.zip`의 `stopped_saturday_0_1/index.html`을 바탕으로 만들었습니다. 원본의 네 출발 경로와 여섯 결말 ID를 이어받고, 새로 시작하는 하루는 열두 번의 선택으로 확장했습니다. 이전 이야기 버전 2의 다섯 선택 기록도 원래 규칙으로 이어서 볼 수 있습니다.

생활 장면과 누적되는 몸의 반응, 실제 이동을 보여 주는 삽화에 이어, 컵의 위치·문 앞에서 기다린 시간·놓친 대화·귀가 여부가 다음 장면에 반영되는 시나리오를 추가했습니다. 고른 시나리오의 핵심 장면 다섯 개 사이에 준비·식사·남은 시간의 활동 등 일곱 단계를 배치합니다. 매번 S01~S13을 모두 보여 주는 방식은 아니며 현재 장소와 조건에 맞는 장면으로 이어집니다.

생활 장면에는 네이버 지도로 입구와 동선을 확인하는 일, 배민의 배달·픽업과 버거킹의 멤버십·쿠폰 조건을 비교하는 점심, 2층 계단을 오를 때 필요한 집중과 상체의 부담을 담았습니다. 짧은 이동에도 힘이 드는 느낌을 인물이 상상하는 에너지 표시로 보여 줍니다.

## 실행

저장소 루트에서 정적 서버를 실행합니다.

```sh
python -m http.server 8000
```

`http://localhost:8000/stopped_saturday/stopped_saturday.html`을 엽니다. 설치·빌드·외부 CDN·로그인·서버 API 없이 실행하며 GitHub Pages 정적 경로를 사용합니다. 설명서는 `stopped_saturday_doc.html`입니다. 파일을 직접 열어도 게임을 진행할 수 있지만 클립보드 등 브라우저 기능은 실행 환경의 제약을 받습니다.

## 설계

- 시작 화면에서 하루의 시나리오와 허구 인물의 시작 조건을 고릅니다. 문·층간 이동·주문 환경은 새 하루를 시작할 때 한 번 무작위로 정하고 기록에 보관합니다. 새 하루는 열두 번의 선택 후 결과에 도달합니다. 선택 후 반응을 읽고 넘기는 동작은 추가 선택으로 세지 않습니다.
- 게임 속 시계는 오전 10:12에 시작해 선택한 활동의 소요 분만큼 진행합니다. 화면은 오전·오후 시각을 표시하며, 일지에는 활동 전후 시각과 소요 시간을 남깁니다. 장면 제목에 맞추려고 시각을 자동으로 건너뛰지 않습니다. 화면을 읽거나 애니메이션을 기다리는 실제 시간은 시계·체력에 더하지 않습니다.
- 신체적 부담, 부탁과 설명, 공동 통행 안전을 각각 행동과 조건으로 남깁니다. 도움 수락·거절·범위 지정, 우회·귀가에 인성 점수나 우열을 붙이지 않습니다. 컵·전화의 위치, 카드 회수, 좌석, 아직 받지 못한 물·식기도 실제 선택을 따라갑니다.
- 에너지·기분과 선택한 행동을 기록합니다. 낮은 에너지는 패배나 선택 잠금으로 이어지지 않습니다.
- 오른쪽 발목, 어깨, 등, 겨드랑이, 손바닥, 몸을 받치는 왼쪽 다리의 상태를 함께 기록합니다. 큰 인체 그림과 카드는 현재 화면에서 숨기고, **부위별 느낌 자세히 보기**를 필요할 때 펼쳐 읽도록 했습니다. 상세는 기본적으로 닫혀 있고 화면을 이동하면 다시 접힙니다. 누적되는 이동 부담, 같은 자세의 뻐근함, 쉬거나 동선을 바꾼 뒤의 부분적인 완화를 문장과 동작에 연결합니다. 이 값은 임상 척도나 신체 시뮬레이션이 아닙니다.
- 여섯 결말은 취미에 몰두하기·말 걸기·외출 방법 확인하기·쉬기·주변 살펴보기·만들기 중 어떤 행동을 골랐는지 반영합니다. 특정 행동 한 번만으로 결말을 결정하지 않습니다. 좋은 결말·실패 결말 구분은 없습니다.
- 목발 이동은 손잡이로 지지하는 삽화이며 겨드랑이에 체중을 매다는 동작을 올바른 보행으로 제시하지 않습니다. 무리한 이동·운전, 의지에 의한 부상 극복을 권하지 않습니다.
- 움직임은 선택 뒤의 유한한 장면입니다. 애니메이션 시간은 상태 변화나 결말에 영향을 주지 않습니다. OS의 움직임 줄이기와 화면 설정을 존중합니다.
- 동작별 모니터는 이야기의 상태 변화를 시각적으로 나눈 표시입니다. 실제 칼로리·대사량을 측정하지 않으며, 애니메이션 재생으로 상태를 반복 차감하지 않습니다. 2층 계단은 일상의 집중·상체 부담·도착 후 피로를 표현하고 보행 기술이나 묘기 순서를 안내하지 않습니다.
- 실제 서비스의 기능·기간 한정 행사와 가상 인물의 경험을 구분합니다. “이날 이 주문에서 적용되지 않는 혜택”을 이야기하며, 배달이 항상 비싸거나 쿠폰이 적다고 일반화하지 않습니다. 사용자의 실제 회원 등급·주소·쿠폰을 읽거나 주문하지 않습니다.
- 선택·결과는 서버로 전송하지 않습니다. 현재 진행과 완료 일지는 이 브라우저에 보관하며, 친구 비교는 미리 확인한 JSON을 사용자가 직접 복사·저장·전달하는 방식입니다. PNG·문구 복사·브라우저 공유도 사용자가 요청할 때만 실행합니다. 로컬 주소나 배포가 확인되지 않은 링크를 공유 문구에 넣지 않습니다.

## 장면과 기록 사용법

| 시작 화면의 하루 | 핵심 장면 순서와 진입 조건 |
| --- | --- |
| 처음의 토요일 (`classic`) | 원본의 네 출발 경로와 여섯 결말을 바탕으로 한 핵심 장면 |
| 창가에서 커피 한 잔 (`home`) | S01 → 컵 도움을 요청했다면 S07 → 집 안의 장면 → S13 → 마무리 |
| 문 너머의 자리 (`doors`) | S02 → S03 → 실제 입장했다면 S09 → 낮은 자리에 앉았다면 S10 → 마무리 |
| 도착한 뒤의 일들 (`cafe`) | S05 → 실제 입장했다면 S06·S09 → 자리에 앉았다면 S10 → 마무리. 휴대전화 결제 선택은 시작 조건에 있을 때만 제시 |
| 같이 걷는 하루 (`company`) | S08 → 실제 출발했다면 S11·S12 → 엘리베이터 앞에 도착했다면 S04 → 마무리 |
| 메뉴보다 먼저 (`planning`) | S13 → S08 → 실제 출발했다면 S12 → 엘리베이터 앞에 도착했다면 S04 → 마무리 |

버전 3의 순서는 **아침 준비 → 핵심 1 → 핵심 2 → 점심 전 확인 → 핵심 3 → 식사 뒤 → 핵심 4 → 남은 시간의 활동 → 다음 끼니 준비 → 핵심 5 → 편히 머무를 자리 → 필요한 물건 정리**입니다. 마지막 두 단계는 추가 외출이나 수면을 강요하지 않으며 앞에서 고른 휴식도 이어집니다.

귀가했거나 출발하지 않은 경로에서는 맞지 않는 문·좌석·동행 장면 대신 현재 집에서 이어지는 장면을 보여 줍니다. 생략 이유는 상태의 `context.skipped`에 남깁니다. S10에서 미룬 물·식기는 다음 식사나 핵심 회고 장면에서 명시적으로 요청해 받거나, 미해결인 채 기록할 수 있습니다. S07은 시작 조건 `helpStyle: 'ask'`에서 상대가 먼저 “다른 것도 해줄까?” 묻는 변형을 보여 줍니다. 귀가 서술은 실제 출발·현재 장소에 맞추며 이동 거리와 걸린 분을 함께 설명합니다.

새 하루와 이어 하기는 시작 화면에서 구별합니다. 완료한 하루는 **토요일 일지**에 저장하고, 새 하루를 시작해도 보관된 일지는 유지합니다. 결과·일지·비교 화면은 선택 번호를 한 번씩 표시하고, 시각·고른 행동·결과 문단·몸의 반응을 구분해 보여 줍니다. 각 기록의 버전에 맞는 선택 수와 결과를 읽거나, 바꾸고 싶은 선택 직전부터 새 기록으로 플레이할 수 있습니다. 그 이후의 선택은 다시 고르며 원본 일지에는 덮어쓰지 않습니다.

해당 장소에 도착하면 무거운 미는 문·자동문·회전문, 계단·에스컬레이터, 카운터·키오스크 중 그 하루에 정해진 환경을 만납니다. 각 환경에 맞춰 기다리거나 직원에게 부탁하고 다른 입구·엘리베이터·주문 방법을 확인합니다. 자동문만 따로 고르는 모드는 없습니다. 새로고침·이어 하기·선택을 바꾼 재플레이는 저장된 환경을 유지하며, 새로운 하루를 시작할 때 다시 정합니다. 모든 환경을 한 번의 플레이에서 반드시 만나는 것은 아닙니다.

자동문이 좌석·거리·대화의 문제까지 해결하지는 않습니다. S12의 다섯 계단이나 에스컬레이터 앞에서는 이 인물에게 맞는 다른 경로를 확인하며 에스컬레이터 탑승을 진행하지 않습니다. 기존 하루의 2층 계단 장면과 시작 상황이 다르며, 모든 사람의 이동 능력이나 실제 시설의 안전성을 하나로 가정하지 않습니다. S09에서 양손으로 목발을 짚어 포장 음식을 가져올 수 없게 된 경로는 음식을 가게에 두고 빈손으로 귀가한 상태를 이후 장면과 일지에도 유지합니다.

친구 비교는 일지의 **친구에게 줄 기록 미리보기**에서 내용을 확인하고 복사하거나 JSON 파일로 저장합니다. 받는 사람이 **친구의 기록 가져오기**에서 파일이나 텍스트를 확인한 뒤 일지에 추가합니다. 같은 시나리오·시작 조건끼리 행동과 결과를 나란히 보여 주고, 조건이 다르면 그 이유를 표시합니다. 초대·게시·전송이나 브라우저·기기 간 자동 동기화는 하지 않습니다.

## 저장 형식과 호환성

`localStorage`의 `websim.stopped-saturday.v1` 키와 `schemaVersion: 1`을 유지하고, 현재 저장 묶음의 `scenarioVersion`은 `"3"`입니다. `current`, `completed`, `replays`, `imported`를 구분하며, 각 기록에 자체 이야기 버전·시작 조건·선택 ID·완료 여부·화면 단계·게임 안의 하루 번호를 보관합니다. 분기 기록에는 `parentId`, `branchIndex`, `comparisonKind`를 함께 둡니다. 현재 장면·게임 속 시각·에너지·조건 플래그는 해당 버전 엔진으로 선택을 재현해 복원하므로 재로딩이 선택 효과나 시간을 중복 적용하지 않습니다. 실제 플레이 시각은 저장 식별 정보로 쓰지 않습니다.

새 시작은 버전 3·열두 선택입니다. 버전 2의 다섯 선택 기록은 이전 엔진으로 이어 하기·완료·분기·내보내기·가져오기를 지원합니다. 알려진 버전 2 저장 묶음은 모든 기록을 검증한 뒤 메모리의 상위 버전만 3으로 바꾸고, 각 기록의 버전·ID·선택·진행 단계는 유지합니다. 저장소를 여는 것만으로 디스크에 쓰지 않으며 다음 명시적 저장 때 반영합니다. 이야기 버전이 다른 두 기록은 같은 조건의 비교로 표시하지 않습니다.

새 버전 3 기록의 조건에는 `doorMode`(`manual`·`automatic`·`revolving`), `verticalRoute`(`stairs`·`escalator`), `orderMode`(`counter`·`kiosk`)와 도움 방식·휴대전화 결제 여부를 담습니다. 이전 버전 3 기록에 `verticalRoute`·`orderMode`가 없으면 없는 채로 보존하고 기존 계단·카운터 장면으로 재현합니다. 다시 열거나 공유할 때 임의의 새 환경을 넣지 않습니다. 이전에 만든 자동문 비교 기록도 읽고 재현할 수 있지만 전용 비교 시작 버튼은 현재 화면에서 제거했습니다.

친구용 JSON은 `schemaVersion`, `scenarioVersion`, `scenarioId`, `conditions`, `choiceIds`의 다섯 필드만 허용합니다. 16 KiB 제한, 정확한 필드·버전·시작 조건과 해당 버전에서 가능한 완료 경로를 검증합니다. 선택 수는 버전 3에서 열두 개, 버전 2에서 다섯 개입니다. 서버 인증이나 사람의 신원을 증명하는 파일은 아니며, 문자열은 HTML로 실행하지 않습니다. 로컬 저장의 지원 범위는 2 MiB·일지 500개입니다. 로컬 전체 백업은 다른 형식으로 현재 진행·일지와 보존 중인 저장 원문을 담고 친구 비교용 가져오기에 쓰지 않습니다.

손상되거나 지원하지 않는 버전의 원문은 자동 삭제·덮어쓰기하지 않습니다. 읽기 전용으로 원문을 보존해 백업할 수 있고, 새 플레이는 현재 탭의 메모리에서 이어집니다. 알려진 버전 2의 호환 처리와 달리 알 수 없는 버전을 임의로 변환하지 않습니다. 저장 공간 차단·쓰기 실패도 화면에 알리고 백업 대안을 보여 줍니다. 이런 경우 탭을 닫기 전에 백업해야 현재 메모리의 기록을 따로 남길 수 있습니다.

초기화·삭제 버튼은 범위를 설명하고 확인을 받은 뒤 동작합니다. **현재 하루 초기화**는 이어 하기만 지우며 완료·다시 플레이한 기록·가져온 일지는 유지합니다. **이 기록만 삭제**는 선택한 일지 하나를 지우고, 그 하루가 마지막 완료 하루라면 해당 이어 하기 표시도 지웁니다. 다른 일지나 진행 중인 별도 하루는 유지합니다. 원본 일지를 지워도 다시 플레이한 기록은 부모 ID를 유지한 별도 기록으로 보관합니다. **보관 기록 전체 삭제**는 내 완료·다시 플레이한 기록·가져온 기록과 마지막 완료 하루의 이어 하기 표시를 지우며, 아직 끝내지 않은 현재 하루는 유지합니다. 친구용 내보내기와 로컬 백업은 기록을 지우지 않습니다. 최신 검증 결과는 [coverage.md](coverage.md)에 기록합니다.
