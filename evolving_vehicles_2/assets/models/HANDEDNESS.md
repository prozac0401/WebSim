# 차량 외형의 좌우 좌표 계약

2026-10-27. 이 문서는 현재 선택 가능한 13종의 원본 좌표와 화면 좌표 사이의 보정을 설명한다. 차체 전체의 좌우가 뒤집힌 문제를 고치며, 차량의 주행 경로·제원·물리나 원본의 수출 시장 트림을 변경하지 않는다.

## 기준 좌표와 원인

서킷 월드는 `+X=동쪽, +Y=남쪽, +Z=위`이고, 차량의 표시 로컬 좌표는 `+X=전방, +Y=차량 오른쪽, +Z=위`다. 따라서 뒤에서 정면으로 본 차량의 `+Y`는 화면 오른쪽이다. 차의 진행각을 `θ`, 경사를 `γ`라 하면 GPU와 Canvas는 같은 변환을 사용한다.

```text
q = (sourcePosition + modelOffset) * modelScale  // 성분별 곱
u = q.x*cos(γ) - q.z*sin(γ)
world.x = car.x + u*cos(θ) - q.y*sin(θ)
world.y = car.y + u*sin(θ) + q.y*cos(θ)
world.z = car.z + q.x*sin(γ) + q.z*cos(γ)
```

기존 일부 빌더는 원본을 `전방/왼쪽/위`로 회전시켰지만 렌더러는 두 번째 축을 오른쪽으로 해석했다. 전후 방향과 차체 치수만 검사하면 발견되지 않는 좌우 반사 문제다. 아래 변환식은 원본 노드의 월드 행렬을 적용한 **뒤**의 축 변환이며, 중심 이동·크기 조정은 생략했다. 행렬식의 부호만으로 임의의 다른 모델을 자동 분류하지 않고, 해당 파일의 원본 방향과 비대칭 형상을 함께 확인한다.

보정 대상 8종은 [`manufacturer-models.js`](../../manufacturer-models.js)의 `legacyLeftAxis`에 명시한다. 이 목록에 있어도 `coordinateTransform.handednessCorrectedForRenderer === true`가 있으면 `+1`을 우선하여 이중 반사를 막는다. 나머지 모델에 이름이나 좌우 대칭 추정만으로 반사를 추가하지 않는다. 718은 현재 공개 실행 모델에 포함되지 않으므로 이 표의 대상이 아니다.

## 원본을 보존하는 적용 방식

- `ManufacturerModels.create()`에서 위 8종의 `modelScale[1]`만 음수로 둔다. `modelOffset`으로 원래 중심을 맞춘 뒤 반사하므로 좌우 범위가 약간 비대칭인 원본도 같은 중심을 사용한다. 압축 실행 파일과 원본 정점 위치·법선·인덱스·bounds는 다시 쓰지 않는다.
- GPU는 위치에 부호 있는 크기 변환을 적용하고, 법선에는 역전치 변환인 `normal / modelScale`을 적용한 뒤 차의 자세를 적용한다. 따라서 표면과 조명이 함께 반사된다.
- 원본에서 만든 `fallbackPrimitives`를 Canvas 면으로 변환할 때 같은 위치 반사를 적용하고, 새 면의 두 번째·세 번째 정점 순서를 교환한다. 원본 인덱스 배열은 그대로다. 별도로 직접 제작한 `VehicleMeshes` 대체 외형은 이미 표시 좌표로 작성되어 있어 다시 반사하지 않는다.
- `VehicleWheels.localWheel()`은 표시용 바퀴 중심뿐 아니라 의미상 `side`에도 가로축 부호를 적용한다. 원본 휠 메타데이터, 앞뒤 구분, 주행 거리로 계산한 회전 위상은 보존한다.
- G70 경광등은 생성할 때 표시 후의 실제 좌우로 적·청색을 선택한다. 차체 보정 때문에 기존 점멸 위상과 물리적 좌우 색상 배치가 반대로 바뀌지 않게 한다.

### 수프라 번호판 한정 예외

기존 수프라 빌더는 차체의 좌우 반사를 그대로 둔 채, 직접 만든 `WebSim_display_plate`의 U 좌표만 반대로 넣어 글자를 읽을 수 있게 했다. 차체 전체를 올바르게 표시하면 이 보정이 중복되므로, `accept()`에서 해당 재질의 U만 `1 − U`로 복원한다. 메인·원본 기반 경량 메시의 번호판에 적용하며, 수프라의 다른 부품 UV는 유지한다. 미래에 이미 보정된 수프라 파일이 위 메타데이터를 제공하면 이 예외도 적용하지 않는다.

### 카니발 PlayCanvas JSON의 V 원점

카니발은 GLB가 아닌 원본 PlayCanvas JSON의 `texCoord0`를 사용한다. [PlayCanvas 공식 JSON 파서](https://github.com/playcanvas/engine/blob/main/src/framework/parsers/json-model.js)는 이 원본을 `(u, 1 − v)`로 바꿔 읽지만 기존 빌더에는 그 단계가 없었다. 이 누락 때문에 번호판이 상하로 뒤집혀 있었으며, 차체의 좌우 보정과 별개인 문제다.

등록할 때 카니발의 **텍스처가 있는 부품에만** `V = 1 − V`를 적용한다. 원본 번호판은 `nameplate` 재질의 `Nameplate`/`Nameplate_` 부품과 `199550372-nameplate.jpg`이며, 다른 36개 텍스처를 포함한 총 37개 이미지 바이트는 원본과 동일하게 유지한다. 다른 차종의 GLB UV나 텍스처 업로드의 전역 `UNPACK_FLIP_Y` 설정은 바꾸지 않는다. `coordinateTransform.uvOriginCorrectedForRenderer === true`이면 이 V 변환을 생략한다. 이 플래그는 `handednessCorrectedForRenderer`와 독립적이므로, 기하만 또는 UV만 먼저 보정한 미래 파일도 나머지 보정을 정확히 받을 수 있다.

## 판별 근거와 범위

- **G70:** 보존 실행 파일의 `Object_34 / chrome2`는 텍스처가 아닌 실제 후면 배지 기하다. 보정 전 뒤쪽 투영에서 `G70`, `3.3T` 글자 자체가 거울상이고 좌우 위치도 바뀌었다. 가로축을 보정하면 `G70`이 뒤에서 본 왼쪽, `3.3T`가 오른쪽에서 정상적으로 읽힌다. [원작 모델](https://sketchfab.com/3d-models/genesis-g70-ded2c8428fb9499ebd2bfc69c5592b02), [원본 출처와 해시](g70-model-source.json), [제네시스 2017 출시 자료·사진](https://newsroom.genesis.com/genesis-g70-resets-expectations-of-customer-focused-performance-and-luxury/)을 대조한다.
- **카니발:** 인도형 원본의 명시적 부품 `56111P2150_RHD_05`는 보존 파일에서 가로축 `−0.6276…−0.2322 m`, 스티어링 휠 로고는 `−0.4937…−0.3662 m`에 있다. 표시 가로축을 보정하면 이 우핸들 부품이 실제 차량 오른쪽에 놓인다. [기아 인도 공식 구성기](https://www.kia.com/in/vr/showroom/index.html)와 [취득 출처](kia-sources.json)의 인도형 RHD 구성을 유지하는 것이다. 이를 국내 좌핸들 모델로 변경한 것이 아니며 실내·휠·배지의 시장별 차이도 그대로다.
- **이미 보정된 모델:** M2의 앞뒤 배지, CN7 N의 뒤 N 배지·번호판, GR86의 뒤 GR 번호판, K5의 뒤 K5 배지 방향은 각 모델 회귀에서 확인한다. 이 네 모델을 다시 반사하지 않는다.
- **토레스:** 원본 사진의 투영 카메라 `right` 벡터가 렌더러의 화면 오른쪽과 일치한다. 메시만 뒤집거나 사진 UV만 뒤집으면 보정된 사진과 형상이 어긋나므로 모두 유지한다.

이 수정은 출처 모델의 형상을 표시 좌표계에 맞추는 작업이다. 커뮤니티 모델을 제조사 CAD로 바꾸거나, 수출 사양을 국내 사양으로 인증하거나, 원본의 모든 비대칭 세부 형상이 실차와 일치한다고 보증하지 않는다.

## 재생성과 검증

기존 `*-runtime.js` 압축 파일, 생성 도구와 원본 해시는 변경하지 않는 것이 의도된 동작이다. 기존 빌더로 같은 파일을 재생성해도 [`manufacturer-models.js`](../../manufacturer-models.js)의 등록·생성 경로를 거치면 같은 표시 결과를 얻는다. 새 빌더가 앞으로 파일 좌표 자체를 보정한다면 원본 법선·와인딩과 비대칭 부품을 함께 확인하고 `coordinateTransform.handednessCorrectedForRenderer: true`를 기록해야 한다. 카니발의 V 원점을 파일에서 미리 보정한다면 별도로 `coordinateTransform.uvOriginCorrectedForRenderer: true`를 기록한다. 요약 파일의 bounds는 표시 후 범위가 아니라 보존 실행 파일의 좌표 범위다.

[`vehicle-handedness.test.cjs`](../../vehicle-handedness.test.cjs)는 8종/4종/사진 모델 분류와 명시 메타데이터 우선권, 실제 G70 기하 보존·카니발 우핸들 위치, GPU/Canvas 좌표와 법선, 경량 메시 와인딩, 휠 중심·회전, 수프라 번호판의 단회 보정, 토레스 사진 카메라 방향을 검사한다. 기존 모델별 검사도 보존 파일과 크레딧의 계약을 계속 확인한다. 실제 화면 검토는 이 좌표 검사와 별도로 수행한다.
