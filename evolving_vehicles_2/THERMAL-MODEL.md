# EV2의 접지·열·소모·회생 모형

이 문서는 `evolving_vehicles_2`의 원메이크 레이스에 적용되는 비교용 모형을 설명합니다. 제조사 시험이나 실차 센서 기록을 재현하는 모델이 아닙니다. 별도 `evolving_drift` 시뮬레이터의 물리·채점·준비 기록은 이 문서의 적용 대상이 아닙니다.

## 주행에 반영하는 상태와 개발용 진단

온도·마모·배터리 상태는 각 차량의 내부 주행 계산에 계속 반영합니다. 공개 주행 화면의 **관찰 차량 상태** 패널과 **랩별 기록과 상태** 표는 제거했습니다. 상세 수치는 개발·검증용 `render_game_to_text()`의 JSON에 남기며, 선택 차량의 현재 상태는 `watchCondition`, 완료한 최근 최대 5개 랩의 상태는 `watchLapConditions`에서 확인합니다.

```js
const { watchCondition, watchLapConditions } = JSON.parse(window.render_game_to_text());
```

다음 경로는 `watchCondition`을 기준으로 합니다. 비율은 0~1, 전력은 W 단위이며 화면용 백분율·kW로 변환된 값이 아닙니다.

| 진단 값 | 의미 |
| --- | --- |
| `tires.front/rear.temperatureC` | 축별 부하와 냉각으로 계산한 추정 온도(℃) |
| `tires.front/rear.remaining` | 초기 상태 대비 남아 있는 내구성. 냉각으로 마모가 회복되지 않음 |
| `tires.front/rear.gripFactor` | 해당 차량의 기본 접지에 곱하는 상태 보정. 절대 마찰 계수나 노면 센서값이 아님 |
| `brakes.front/rear.temperatureC` | 실제 마찰제동이 담당한 에너지와 냉각의 결과(℃) |
| `brakes.factor` | 초기 제동 능력 대비 열·마모 보정 |
| `powertrain.powerFactor` | 해당 구동계의 상태에 따른 출력 한도. 현재 악셀 사용률이 아님 |
| `powertrain.soc` | 전기·하이브리드 모형이 적분한 충전량. 내연기관 전용 차량은 `null` |
| `power.regenW`, `power.frictionBrakeW` | 현재 감속을 나누어 담당하는 기계적 출력(W) |
| `power.engineChargeW` | HEV에서 엔진 발전 후 배터리에 저장하는 전력(W). 회생과 별도 |

성능 제한 원인은 `limitations`에 기록하며, 완료한 랩의 상태와 비교할 수 있습니다. 완주·중단 후에는 마지막 상태를 유지합니다. 하이브리드의 기존 충전·사용 게이지도 상태 모형의 충전·방전 흐름을 사용합니다. 이 게이지의 길이는 SOC가 아닙니다.

## 계산의 연결

1. 노면·경사·속도·전후 하중과 구동축에서 사용할 수 있는 접지 한도를 구합니다.
2. 코너링에 필요한 횡력을 사용한 뒤 남은 여유로 가속·제동을 제한합니다. 출력이 크다는 이유만으로 고정 언더스티어 페널티를 더하지 않습니다.
3. 실제 구동·감속과 축별 부하로 온도·소모·배터리 상태를 갱신합니다.
4. 변한 접지·제동·출력 한도를 코너 속도와 제동 계획에 반영합니다. 브레이크가 과열되어 제동력이 줄면 앞쪽부터 감속해야 합니다.

차량은 여전히 계산된 주행선을 따르는 독립 고스트입니다. 동적인 조향각·차체 슬립·휠스핀·스핀을 직접 적분하는 차량 모델은 아닙니다. 접지 한도를 넘는 요구는 사용할 수 있는 힘으로 제한합니다.

## 타이어와 브레이크

타이어는 앞·뒤 온도와 마모를 각각 가집니다. 가속·회생·마찰제동·코너링을 전달한 부하에 영향을 받습니다. 차량 중량과 구동축은 실제 하중·힘 계산을 통해 반영하며, 전기차라는 이름에 고정 마모 배율을 붙이지 않습니다. 타이어 규격을 이용한 차이와 내구성 계수는 모두 비교용 추정입니다.

브레이크 온도·마모는 **마찰제동이 처리한 에너지**로 계산합니다. 회생제동이 담당한 부분, 공기저항·구름저항·오르막으로 생긴 자연 감속을 패드 발열에 중복으로 더하지 않습니다. 온도가 낮아지면 열에 의한 성능 저하는 회복되지만 마모는 남습니다. 일찍 브레이킹한다고 같은 속도 차이에 필요한 제동 에너지 자체가 사라지는 것은 아닙니다.

`estimated-v2`는 기존 속도별 대류 냉각에 고온에서 커지는 복사 냉각을 더합니다. 복사 손실은 `εσA(T⁴ − 외기T⁴)`이며 온도는 켈빈입니다. 앞·뒤 축의 유효 복사 면적은 각각 0.30·0.24 m², 방사율은 0.7로 가정합니다. 이는 차종별 측정값이 아닌 공통 추정치입니다. 발열 에너지·열용량·제동 성능 저하 기준은 그대로 두며, 온도를 임의 상한에 고정하지 않습니다. 브레이크 온도는 축별 하나의 등가 온도이므로 디스크 표면의 순간 최고 온도나 캘리퍼 온도로 해석하지 않습니다.

복사 냉각은 최대 0.1초 간격으로 중간 온도에서 다시 계산합니다. 실제 주행의 120 Hz 고정 간격은 유지하여 재생 속도가 냉각량을 바꾸지 않도록 합니다. 제동하지 않는 주행 중에도 냉각하며, 일시정지·완주 후에는 다른 물리 상태와 함께 멈춥니다. 대류와 복사를 함께 다루는 배경은 [COMSOL의 디스크 브레이크 열전달 예제](https://doc.comsol.com/6.4/doc/com.comsol.help.models.heat.brake_disc/brake_disc.html)를 참고했습니다. 이 예제가 위 면적·방사율이나 수프라의 실제 온도를 검증한다는 의미는 아닙니다.

브레이크 단계는 기존 기본 제동력에 더해 열·소모를 견디는 능력을 높입니다. 그립 단계는 기존 접지·공력 효과와 함께 내구성을 높이는 게임 규칙입니다. 현실에서 접지력과 수명이 언제나 함께 높아진다는 주장은 아닙니다. 가속 단계는 설치된 출력이라는 이유만으로 고정 발열을 더하지 않고, 실제 사용한 구동 부하가 열을 발생시킵니다.

## 전기·하이브리드와 내연기관

전기차는 배터리 충전량·온도와 모터 열 상태에 따라 실제 사용 가능한 출력과 회생 한도가 달라집니다. 하이브리드는 배터리·모터 보조의 에너지 한도를 사용하고 부족한 부분은 가능한 엔진 출력 범위에서 담당합니다. 충전량이 낮고 요구 부하가 작은 구간에서는 엔진의 남는 출력으로 제한적으로 충전합니다. 엔진 기계적 일·발전 손실·열을 함께 기록하며 회생 충전과 구분합니다. 제동 중에는 엔진 충전을 겹치지 않고, 충전량이 목표에 가까워지면 줄입니다. 내연기관에도 추정 냉각·열 출력 제한을 적용합니다.

요구 제동력은 회생 가능량과 타이어 접지 한도 안에서 회생으로 먼저 담당하고, 나머지를 마찰 브레이크가 처리합니다. 배터리 수용 능력이 부족하면 회생이 줄어들어 마찰 브레이크의 분담이 늘어납니다. 회수에는 손실이 있으며 배터리의 빈 용량보다 더 저장할 수 없습니다. 실제 배터리 방전·충전과 기계적 회생/마찰제동 에너지는 별도로 기록합니다.

내리막 위치에너지는 기존 경사 힘으로 반영합니다. 경사로 인해 실제 제동이 필요해진 부분이 회생과 마찰제동으로 분담되므로 같은 위치에너지를 발열 항목에 다시 더하지 않습니다. 오르막에서 속도가 줄어도 구동력이 양수라면 그 구동 일을 소비량에 포함합니다.

## 초기 상태와 평가의 공정성

- 상태는 각 차량의 측정 동안 여러 랩에 걸쳐 누적됩니다. 랩 통과만으로 온도·마모·충전량이 초기화되지 않습니다.
- **새 측정**에는 같은 초기 조건을 사용합니다. 새 실험, 같은 구성 재주행, 다음 세대, 출고 상태 자동 반복에서 초기화합니다.
- 빠른 평가와 눈으로 보는 주행은 같은 조건 계산을 사용합니다. 재생 속도나 프레임 배치에 따라 소모량이 달라지면 안 됩니다.
- 일시정지는 시뮬레이션 시간도 멈추므로 냉각이나 마모가 진행되지 않습니다.
- 상태는 레이스의 가변 상태이며 동결된 출고 제원 객체나 튜닝 유전자에 기록하지 않습니다.

기본 초기값은 외기 20℃, 타이어 45℃, 브레이크 70℃, 엔진 90℃, 모터 45℃, 배터리 25℃입니다. 전기차는 SOC 80%, 하이브리드는 60%에서 측정합니다. 제조사 권장 온도나 공인 테스트 조건이 아니라 비교를 위한 고정된 예열·충전 가정입니다. 하이브리드의 용량이 확인되지 않았으면 1.5 kWh, 전기차 용량이 없으면 60 kWh를 추정 기본값으로 사용합니다. UI에 차량별로 확인된 용량과 이 추정을 혼동해 표시하지 않습니다.

## 비용과 한계

네 튜닝 축의 기존 비용·보상·상한은 이번 작업에서 바꾸지 않습니다. 이전 물리의 비용 실험에서 제안된 가속 3단계 16P는 적용하지 않습니다. 새로운 물리에서 1·3·5랩, 노면, 차종·사양을 다시 비교해야 비용 변경의 타당성을 판단할 수 있습니다.

열 용량·냉각률·마모율·출력 제한·배터리 수용 한도는 추정 모델 파라미터입니다. 실제 차량의 안전한 온도·제동거리·타이어 수명·고성능 지속 시간을 예측하지 않습니다. 실제 차종별 냉각 회로·BMS·ABS/ESC·토크 배분·회생 협조제어를 재현하지 않습니다. 연료 감소, 피트 정차·부품 교환, 날씨·노면 온도 변화도 이 초기 범위에 포함하지 않습니다.

## 검증해야 할 결과

- 코너링과 가속·제동이 접지 여유를 공유하고 축별 힘이 한도를 넘지 않는지.
- 같은 차종·시드·설정의 결과가 반복·프레임 배치·재생 속도에 독립적인지.
- 브레이크가 가열되면 성능과 제동 계획이 바뀌고 냉각 시 회복하는지.
- 회생이 마찰 브레이크의 에너지·발열을 줄이고 타이어 감속 부하는 남기는지.
- 배터리의 충전·온도 한도가 실제 회생·추진에 적용되는지.
- HEV 엔진 발전 충전량에 실제 엔진 일·변환 손실·발열이 대응하고, 바퀴 회생 에너지로 잘못 기록되지 않는지.
- 중량·경사가 에너지와 하중에 한 번씩만 반영되는지.
- 한 랩 이후에도 상태가 누적되며, 새 측정은 정확히 초기화되는지.

자동검사와 브라우저 관찰은 모형의 구현 검증이며 사람의 재미·만족도 검증은 아닙니다. 실제 실행 결과는 PR과 검증 기록에 구분해 남깁니다.

## 2026-10-30 고온 브레이크 냉각 수정 검증

`qa/brake-cooling-20261030/check.cjs`로 같은 인제 4랩을 수정 전후 비교했습니다. 순정 수프라의 마지막 앞 브레이크 온도는 848→751℃, 순정 G80 2.5T AWD 20인치는 850→746℃였습니다. G80의 마지막 랩 온도 범위는 767~860→650~758℃입니다. 사진 속 튜닝 단계는 확인되지 않아 사진의 902·914℃를 정확히 재현한 비교는 아닙니다. 제동 계획도 온도에 반응하므로 두 주행의 총 제동 에너지는 같지 않습니다.

별도로 851℃에서 78 km/h를 유지하며 제동하지 않는 조건에서는 60초 후 673→611℃로 내려갔습니다. 이 비교는 제동 에너지가 모두 0이므로 냉각 차이를 직접 보여 줍니다. 과열이 전부 사라지거나 실차의 적정 온도를 검증한 결과는 아닙니다. 원본과 수정 결과는 `baseline.json`, `after.json`, `g80-baseline.json`, `g80-after.json`에 소스 해시와 함께 저장했습니다.

단위 검사 22개와 실제 주행 통합 검사 13개에서 냉각·회복·에너지 보존·고온 가열·긴 시간 간격의 안정성·1배속/16배속 동일성을 확인했습니다. 상태판 제거 전 v2에서는 브라우저 상태판·정지/재생·초기화·EV/HEV·320/390px 화면 검사 12개도 통과했습니다. 이때의 화면 증거는 `output/playwright/brake-cooling-condition/` 및 `output/playwright/brake-cooling-client/`에 있습니다. 상태판이 보이는 캡처는 과거 UI 증거이며 현재 공개 화면을 나타내지 않습니다.

## 2026-10-30 최초 v1 렌더링 확인

아래는 상태판을 공개하던 최초 v1의 검증 기록입니다. 현재는 상태판과 랩별 상태 표를 제거했으며, 해당 수치는 개발용 진단 JSON으로 확인합니다.

`tests/ev2-condition.browser.cjs`의 소스 기반 UI 회귀 12개 그룹을 Chromium 151.0.7922.34에서 통과했습니다. 데스크톱 1440×1000, 터치 에뮬레이션 320×740·390×844를 사용했습니다. 실제 보이는 시작·일시정지·1초 진행·64배속·빠른 평가·초기화·차량/사양/예산/랩 선택을 조작했습니다. 전기차 3랩 완주 후 기록 3행과 상태 스냅샷, HEV 엔진 일과 발전 충전 표시, 캔버스 밖 상태판, 가로 넘침과 차량 가림을 확인했습니다. 페이지·콘솔 오류와 HTTP 오류는 각각 0입니다. 여섯 런타임 자원의 HTTP 응답 SHA-256이 최종 로컬 소스와 같은지도 확인했으며, 최소 검증 기록은 `qa/condition-20261030/browser-report.json`에 포함했습니다.

증거는 `output/playwright/ev2-condition/report.json`과 데스크톱·모바일 전체 화면 및 `*-panel.png`에 보관합니다. 한국어 글꼴이 없는 초기 QA 환경에는 Noto CJK를 추가한 뒤 다시 캡처했으며, 최종 상태판과 3랩 기록을 직접 확인했습니다. 초기에 브라우저 설치/실행 환경이 막힌 기록과, HEV가 초기 SOC 60% 저부하에서 배터리 대신 엔진만 사용하는 경우를 잘못 단정한 시험 실패는 별도 실패 증거 폴더에 남겼습니다. 최종 시험은 그 상황의 실제 엔진 일과 UI 값의 일치를 검증합니다.

현재 브라우저 회귀 검사는 `/WebSim/` 경로를 제공하는 정적 서버를 실행하고 다음 명령을 사용합니다. 위 상태판 캡처는 제거 전 버전의 기록이며, 현재 검사는 공개 화면에 진단 패널이 없고 내부 상태가 계속 계산되는지 확인합니다. 로컬 기본 Playwright Chromium을 사용할 수 없으면 `CHROMIUM_EXECUTABLE`에 설치된 headless Chromium 실행 파일을 지정합니다.
