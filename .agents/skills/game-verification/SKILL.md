# Routine Bot verification

Work from the WebSim repository root. Read `routine_bot/README.md` for execution semantics and `routine_bot/LEVELS.md` for each level's intent, reference program, command budget, and execution budget. Treat saved data as untrusted. Do not replace a failing assertion with a weaker one to obtain a pass.

Prerequisites: Node.js, a Chromium browser supported by Playwright, and Playwright available locally or through the existing develop-web-game runtime. The game itself has no runtime dependencies. This skill lives in `.agents/skills`; invoke it as `$game-verification` when the project skill catalog is refreshed. If this session does not discover newly created skills, explicitly read this file and execute the same procedure; report that limitation rather than claiming automatic loading.

## Run and preserve evidence

1. Create an evidence directory `output/playwright/routine-bot/<phase>/`, where phase is `early` for the first playable integration or `final` for the completed catalog. Run `node --test routine_bot/*.test.cjs tests/routine-bot-server.test.cjs`. Save stdout and the exact command as `unit-tests.txt` in that directory. Engine tests must compare hand-derived coordinates, directions, and event order, not only the engine against itself. Level tests execute all reference programs through the production engine; label these as solution verification, not exploratory play.
2. Run `node tests/routine-bot-server.cjs` in another terminal. Its mounted URL is `http://127.0.0.1:8123/WebSim/`, matching the GitHub Pages project prefix. Run `node tests/routine-bot-deployment.cjs early` or `node tests/routine-bot-deployment.cjs final` to match the phase; the script otherwise defaults to `final`. This checks the actual menu link, game files, and local relative resources over HTTP. Save stdout as `deployment.txt` in the matching phase directory.
3. Run `node tests/routine-bot.browser.cjs early` or `node tests/routine-bot.browser.cjs final`. This is the separate rendered/UI suite: pause, reset, level-switch cancellation, retention of programs, desktop and touch controls. In the final phase also run `node tests/routine-bot-safety.browser.cjs` for multi-map transition cancellation and editor/runtime limits; its screenshots/report go under `output/playwright/routine-bot/final/safety/`. That safety replay uses a disclosed access fixture for later levels, so it is not full-progression or blind-play evidence. Set `WEBSIM_URL` only when testing a different static origin; preserve the `/WebSim/` prefix. Keep screenshots and the JSON reports produced by the suites.
4. Record PASS/FAIL/NOT RUN per category in `routine_bot/VERIFICATION.md`, with evidence paths and environment. Re-run affected tests after each fix and retain the observed failure and correction in the report. A tool setup failure is NOT RUN, never a game pass. Local static HTTP evidence is distinct from the deployed public site's smoke test.

For inline editor-tree changes, also run `node tests/routine-bot-tree.browser.cjs` (default evidence `output/playwright/routine-bot/tree/`). It covers retained surrounding commands, nested/sibling edits, separate condition branches, collapse while editing a descendant, hidden insertion prevention, repeat changes after a rejected edit, undo/reload, touch and keyboard. Expansion buttons (`data-enter`) only change visibility; branch insertion controls (`data-insert`) choose the target. Repeat selectors belong to each node (`data-repeat`). Do not use flat `.block:last-child` selectors against a recursive tree; select an observed node id or explicit sibling scope.

For block gestures, run `node tests/routine-bot-swipe.browser.cjs`. Verify swipe deletion commits only on release beyond the horizontal threshold, preserves vertical scroll, and is undoable with subtrees. Drag moves must resolve current IDs, reject self/descendant targets before removal, preserve node count/IDs, adjust same-list indices, and pass existing depth/call validation atomically. Check canceled pointers and editor rebuilds cannot commit stale actions, synthesized clicks do not act on replacement siblings, and rest/help locks hold. Keep native mouse/touch input distinct from DOM-event or program injection; old-save fixtures are migration evidence only.

For command-budget or save-migration changes, also run `node tests/routine-bot-budgets.browser.cjs` (default evidence `output/playwright/routine-bot/budgets/migration/`). The hard per-level caps equal the reference-program node counts, not a proved minimum. The suite seeds an old over-budget save only as migration input, then uses visible desktop/touch controls to test blocked run/step/add, partial deletion while still over cap, undo, reload, and a real win after repair. Its separate level-4 access fixture demonstrates that a two-block repeat solves where a flat sequence cannot fit. Preserve the fixture classification; do not call migration injection player-authored code or end-to-end progression. Set `WEBSIM_EVIDENCE` to a fresh directory for each rerun and run browser suites sequentially when trace collection competes for resources.

For timed hazards, run `node tests/routine-bot-hazards.browser.cjs` (default evidence `output/playwright/routine-bot/hazards/focused/`) after the engine/level tests. Check three separate values: saved nodes, executed steps and `movementCount` logical time. Only forward/turn/wait consumes time; repeat/condition/call/return does not. Verify wait omission fails and UI repair succeeds, staying on an activating cell fails, current/next symbols and timetable agree, pause/speed/wall-clock delay do not change logical time, reset/level/next-map return to time zero, and rendered robot/hazard time never rewinds when changing speed after a completed animation. Compare failure-before-success precedence on a hazardous home and initial active cells with the independent engine tests. `hazards.test.cjs` must keep hand-expected failure coordinates/times for selected production levels, not only reference success checks. Preserve wait blocks through save, backup and denied storage tests.

## Cooperation, curriculum and active-time extension

Use `early` and `final` evidence phases for feature integration, not fixed level counts. Discover the ordered catalog by stable ID; retain independent reference expectations for legacy IDs 1–15. Run `node --test routine_bot/*.test.cjs tests/routine-bot-server.test.cjs`, including cooperative collision and timing/migration tests. Run the focused cooperation browser suite as well as the original tree, budgets, hazards and cancellation suites. Save the exact command and stdout for both integration phases.

The concrete UI suite is `node tests/routine-bot-cooperation.browser.cjs early|final`; `WEBSIM_EVIDENCE` selects a distinct rerun directory. Also run `node tests/routine-bot-visibility.browser.cjs` to test actual visible/hidden tab transitions in isolated Chromium; Playwright's focus emulation can otherwise keep the page visible. Do not substitute a synthetic visibility event for this check. The app checkpoints on `pagehide`, so access/migration fixture writes must be applied once on the next document before app startup; writing localStorage then reloading a live page can be overwritten correctly by its final checkpoint. Keep this fixture change separate from product regressions. Capture evidence of the last blockage even after exhaustion, current context tutorial routing, unchanged assistance after completion and cleared visible hints on a new record.

- A cooperative step fixes the whole starting board, independently evaluates each robot to one physical intent, resolves all conflicts, commits atomic robot/box moves, ticks hazard time once, checks hazards, then checks every home and target together. Test intent destination conflicts, same-box pushes, swaps, vacated-start occupancy, directional chains, independent unrelated actions and permuted robot arrays against hand-derived outcomes. Test independent branches, repeat and call frames, ended robots, and control-only evaluation limits.
- Verify every catalog map through the production runner. For a claimed necessary feature, record the public grammar and budgets plus a complete bounded search or valid impossibility argument. A reference using the feature or search timeout is not a proof. Preserve the known function-free level-12 alternative.
- Time with an injected monotonic clock. Retry/reset must retain accumulated time, attempts and assistance. Test overlapping hidden/help/rest exclusions, explicit rest locking, reload/level navigation, faster equal-node records, first records, assisted/unassisted separation and map/rule version separation. Legacy missing time stays absent.
- Seed saves only for disclosed migration/access fixtures. Assert old stable IDs still refer to the same maps and programs, old completed access survives inserted lessons, and new IDs are separate challenges. Confirm real UI controls start a timed challenge, pause for help/rest, resume explicitly and reach success with a visible record.

## Required decision points

- Engine: movement/rotation, boundary and wall collision, condition evaluation before its selected branch, both branches of blocked and marker conditions, minimum/maximum repeat counts, function entry/return order, original solo immediate goal termination, unsupported command rejection, program/depth/step budgets, and rejection of direct/indirect recursive calls.
- Cancellation: start then pause, reset, or change levels during delayed execution; wait longer than the old delay and ensure the old robot, count, event, or completion never returns. Reset must preserve the program. A separate clear action removes it.
- Persistence: round trip all supported blocks/settings, reload level programs and completion, malformed JSON, unknown version, invalid structure, hostile/deep/oversized values, unavailable storage, failed writes, and recovery from the last valid backup. A legacy code exceeding only its newer per-level cap must stay editable/saved and must not execute until repaired; test partial repairs and undo/reload without silent deletion. Failed storage must leave play responsive and tell the player what was not saved.
- Levels: verify every map of every level with one unchanged reference program per level, within declared hard budgets. Check each reference count equals its level cap and cap+1 is rejected before execution, while smaller valid alternatives remain allowed. Keep global size/depth/runtime safety tests independent of the smaller level caps. Record stored node count separately from executed instructions. Do not label a target “optimal” without proof.
- Integration: menu entry and return link, the project prefix, HTTP file/MIME availability, no missing game assets, and unchanged existing-game smoke checks.

Safety, false wins, unsolvable levels, lost saves, broken mobile editing, and broken existing menu/game paths block completion. Fix the cause and re-run its regression; do not hide exceptions. Browser usability and fun observations belong to `$game-playtest`, not this logic report.
